Contrato de la API REST que comparten las tres apps del Proyecto Final (Vendedor, Portal del Cliente y Supervisor). Amplía la API del parcial (Semana 8, versión 1.0.0) sin romperla: los endpoints del parcial se mantienen.

Convenciones

  • Autenticación: Authorization: Bearer <token JWT> en todas las rutas, salvo /api/salud, /api/auth/login y /api/portal/registro. El token lleva id, nombre y rol.
  • Roles: vendedor, supervisor, agente (servicio al cliente) y cliente (Portal). El rol se valida en el servidor; la app solo oculta lo que el rol no puede usar.
  • Idempotencia: toda escritura (POST, PUT, DELETE) envía la cabecera X-Operacion-UUID. Si la misma operación llega dos veces (reintento del SyncWorker), la API devuelve la respuesta guardada con X-Operacion-Duplicada: true y no repite nada.
  • Concurrencia: las entidades editables traen version. La app envía la versión que tenía; si no coincide, la API responde 409 CONFLICTO_VERSION con el dato actual.
  • Errores: siempre {"error": "CODIGO", "mensaje": "texto para el usuario"}.
  • Fechas: ISO-8601 (2026-11-04, 2026-11-04T15:30:00Z). Montos: soles, 2 decimales.
  • Listas: {"servidorTiempo": "...", "total": n, "datos": [...]}; un objeto: {"dato": {...}}.

Caso académico: empresas, clientes y montos son ficticios.
